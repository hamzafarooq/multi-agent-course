# Reference brief — Ghost

**Company URL:** https://ghost.org
**Repo URL:** https://github.com/TryGhost/Ghost
**Language(s):** TypeScript (18.8 MB) and JavaScript (18.0 MB), with CSS, Handlebars (themes), HTML, Shell, MDX. GitHub reports TypeScript as the primary language. 55,260 stars, 11,951 forks, 184 open issues, MIT license, last push 2026-09-10.

---

## What it does

Ghost is an open-source publishing platform for people who write on the web and want to own their audience. A writer sets up a site, writes posts in a distraction-free editor, and publishes them to a public website and optionally as an email newsletter. Readers can become members by entering their email — Ghost has no passwords for members; it emails them a magic link — and members can be free or paid (via Stripe, with Ghost taking "0% payment fees"). It positions itself against Substack and Medium with the headline "Turn your audience into a business" and describes itself as "The best open source blog & newsletter platform". It is used by independent publications such as 404 Media (footer: "Published with Ghost"), Platformer, The Lever, Tangle and The Browser, and is sold as a hosted service, Ghost(Pro), from $18/month, or self-hosted for free.

## Core user flow

This is the loop the Sprint Zero build reproduces (site, draft-to-published post, public reading, free membership), plus our "Ask me" addition, which Ghost does not have.

1. **Set up the site.** The owner installs Ghost (or signs up for Ghost(Pro)), and the setup screen creates the Owner staff user with email and password and asks for a publication title. In Settings → Site → Design & branding the owner sets the "Publication title", description, "Accent color", publication icon, logo and cover image. These are rows in the `settings` table (`title`, `description`, `accent_color`, `logo`, `icon`, `cover_image`, `navigation`, `heading_font`, `body_font`, `locale`, `timezone`). A fresh install defaults to title "Ghost", description "Thoughts, stories and ideas" and accent `#FF1A75`.
2. **Write a post.** From the admin Posts list the owner clicks "New post" and lands in the editor: a title field and a body canvas, with "‹ Posts" back link and a "Draft" label at top-left, and "Preview" and "Publish" at top-right. Ghost autosaves continuously. A new post has `status: 'draft'` (the model default), and drafts are invisible to readers.
3. **Publish it.** The Publish menu offers publishing to the site, sending as an email newsletter, or both, and a "Schedule for later" option. Publishing sets `status` to `published`; the model sets `published_at` to now if it is empty and records `published_by`. The post appears at `/<slug>/` on the public site immediately. "Unpublish" reverts it to a draft. Statuses are `draft`, `published`, `scheduled`, `sent` (email-only).
4. **A reader visits the public site.** No account is needed. The theme (Casper by default) renders the home page — header with site title/logo, nav, "Sign in" and a "Subscribe" pill; an accent-coloured cover with the title and description; a feed of post cards — and the post page with title, excerpt, byline with avatar, date and reading time, feature image, and a single 720px reading column. Every page is served from Ghost's Content API data, which is public and read-only.
5. **The reader becomes a free member.** They click "Subscribe" (header pill, floating Portal button, or the "Sign up for more like this." email box at the bottom of each post). Portal opens a modal, asks for email (and optionally a name), and the reader clicks "Continue". Ghost emails a magic link; the confirmation page says "Now check your email!". Clicking the link creates a `members` row with `status: 'free'` and signs them in. The default access setting is "Anyone can sign up".
6. **Return and read as a member.** Signed-in members can read "Members only" posts, manage their newsletter subscription and account in Portal, and receive published posts by email if a newsletter is enabled. Ghost also ships site search (⌘/Ctrl + K) over post titles and excerpts, tags and authors — a lookup, not an answer. Sprint Zero's "Ask me" box (full-text search over published posts, optionally with Claude composing a cited answer) is our addition, not a Ghost feature.

## How it works (high level)

- **One Node.js server, two JSON APIs.** Ghost's docs describe it as "a RESTful JSON API — designed to create, manage and retrieve publication content". The **Content API** (`/ghost/api/content/`) is public and read-only, authenticated by a key passed as a query parameter that is "safe for use in browsers"; it only ever returns published, public data. The **Admin API** (`/ghost/api/admin/`) is read/write and authenticated by a staff session cookie, a staff access token, or an integration's Admin API key (a short-lived JWT). A third small **Members API** (`/members/api/`) handles magic-link sign-in and the member's own account.
- **Server-rendered theme layer plus separate client apps.** The public site is rendered by an Express + Handlebars theme layer (themes are folders of `.hbs` files; Casper and Source ship as git submodules). The admin is a separate single-page app (a React admin in `apps/admin` is replacing the legacy Ember admin), and small embeddable apps — Portal (membership modal), sodo-search (search modal), comments-ui, signup-form, announcement-bar — are injected into any theme as scripts loaded from a CDN.
- **Relational data through an ORM.** Bookshelf/Knex over SQLite in development and MySQL in production. The schema (`ghost/core/core/server/data/schema/schema.js`) defines 95 tables; settings are a key/value table grouped by area rather than columns on a site row.
- **Memberships are passwordless and Stripe-backed.** Members authenticate by email link or one-time code, are stored separately from staff `users`, and paid access is modelled as tiers (`products`) with Stripe prices; content gating is enforced server-side by post `visibility`.

## Data model (if repo provided)

From `ghost/core/core/server/data/schema/schema.js` (95 tables) and `default-settings.json`. The entities that matter for our loop:

- **settings** — key/value rows: `id`, `group`, `key` (unique), `value` (text), `type` (array/string/number/boolean/object). The `site` group holds `title`, `description`, `accent_color` (default `#FF1A75`), `logo`, `icon`, `cover_image`, `navigation`, `heading_font`, `body_font`, `locale`, `timezone`; the `members` group holds `members_signup_access` (default `all`) and `default_content_visibility` (default `public`); the `portal` group holds `portal_plans` (default `["free"]`), `portal_button`, `portal_name`. There is no "site" table — one Ghost install is one site.
- **users** (staff) — `id`, `name`, `slug`, `password` (bcrypt), `email`, `profile_image`, `bio`, `status` (`active`, `inactive`, `locked`, `warn-1..4`), `last_seen`. Linked to **roles** via `roles_users`; fixture roles are Owner, Administrator, Editor, Author, Contributor.
- **posts** — `id`, `uuid`, `title`, `slug`, `lexical`/`mobiledoc` (source), `html`, `plaintext`, `custom_excerpt`, `feature_image`, `featured`, `type` (`post` | `page`), `status` (`published` | `draft` | `scheduled` | `sent`), `visibility` (public / members / paid / tiers), `created_at`, `updated_at`, `published_at`, `published_by`, `newsletter_id`, `email_recipient_filter`, `canonical_url`, `codeinjection_*`. Authors via **posts_authors**, tags via **posts_tags**, SEO fields in **posts_meta**, versions in **post_revisions**. The Content API adds computed `excerpt`, `reading_time`, `url`, `primary_author`, `primary_tag`.
- **members** (readers) — `id`, `uuid`, `transient_id`, `email` (unique), `name`, `note`, `status` (`free` | `paid` | `comped` | `gift`), `email_count`, `email_opened_count`, `email_open_rate`, `email_disabled`, `last_seen_at`, `created_at`. Newsletter subscriptions in **members_newsletters**; labels in **members_labels**; paid state in **products** (tiers), **members_products**, **subscriptions**, **members_stripe_customers**. The Admin API says "At minimum, an email is required to create a new, free member" and new members default to `status: "free"`.
- **newsletters** — name, description, sender settings, design settings; a "Default Newsletter" fixture exists. **emails**, **email_batches**, **email_recipients** record sends.
- **tags**, **collections**, **comments**, **recommendations**, **offers**, **integrations** / **api_keys** / **webhooks**, **sessions**, **tokens** (magic-link and one-time codes), plus ~40 `members_*_events` tables that feed the activity feed and analytics.

Relationships in one line: a site has many staff `users` (one Owner) who write many `posts`; `posts` have authors and tags and a `visibility`; `members` are separate from `users`, belong to `newsletters` and optionally to `products` (tiers); `settings` describe the site.

## Who it's for

The person setting it up is an independent writer, journalist or small publishing team (one owner, a few staff) who wants a site and newsletter they own, and either pays for Ghost(Pro) or is comfortable running `ghost install` on a server. The end user is a reader who arrives at a public URL, reads posts without an account, and hands over an email address to become a free member (or a card to become a paid one) so posts reach their inbox and gated content unlocks.

## Things worth flagging

1. **No question answering exists in Ghost — "Ask me" is our addition.** Ghost's only reader-facing retrieval is sodo-search: a client-side flexsearch index over post *titles and excerpts* (not body text), capped at 10,000 posts, returning links. Our Ask me box (SQLite FTS over full published post text, optional Claude answer with citations) has no Ghost equivalent and should be specced as new behaviour, not a clone. The only LLM-adjacent things in the repo are an `llms_enabled` site setting (an `llms.txt`-style exposure of content to crawlers) and a `docsbot-widget-host.tsx` help widget in the admin; neither answers reader questions.
2. **Settings are a key/value table, not a site row.** One Ghost install is one publication; `title`, `description`, `accent_color` live as `settings` rows and are the only "site" object. Our build has many sites per install (each writer creates one), so we need a real `sites` table with those three fields plus an owner, which Ghost does not model.
3. **Members and staff are separate identity systems.** Staff (`users`) log in with email + password to `/ghost/`; members log in passwordless via magic link or code and never see the admin. Our scope collapses this: the writer has a password account, the reader has an email-only membership, and both are simple, but keep them as two tables so the public site never exposes staff auth.
4. **Publishing has real rules worth copying.** `published_at` is set to now on the draft→published transition if empty; `published_by` records who; unpublish returns to `draft`; the public API only ever sees `status:published` and `visibility:public` for anonymous readers. Reproduce exactly those two filters and nothing more (no scheduled or sent states).
5. **The look is Casper, not ghost.org.** The marketing site is Inter-style dark-on-white with a black CTA button; the product a reader sees is Casper: system sans-serif headings at weight 800, Georgia body text at 20px, a 1200px container and 720px reading column, an accent colour that paints the cover, header and links, and a pill "Subscribe" button. Numbers are in the section below and in `.sprint-zero/design/ghost-tokens.md`. Ghost's editor is a plain white canvas (one centered column, title + body), which is a good target for our plain-textarea editor.
6. **Heavy dependencies we are cutting.** Mailgun (email sending), Stripe (payments), Tinybird (analytics), MySQL/Redis (production data), a Lexical rich editor, and a Handlebars theme engine. The scope's exclusions line up with all of these; the members' in-app feed replaces email.
